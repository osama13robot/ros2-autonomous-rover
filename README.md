# ROS 2 Autonomous Rover

**A 3D-printable robot you can simulate, drive, and watch map a house by itself, built to learn ROS 2 from.**

This repository is a complete, working ROS 2 workspace for a small differential-drive robot.
It covers the whole stack, from the printable STL files to autonomous exploration, and every piece is
documented so you can understand it and change it.

## Features

| | |
|---|---|
| 🖨️ **3D-printable hardware** | 9 printed parts generated by a parametric Python script, all fitting a 220 × 220 mm bed, with a BOM and assembly guide |
| 📐 **One source of truth** | a single `dimensions.yaml` drives the printable parts *and* the simulated robot, so they never disagree |
| 🌍 **Gazebo Harmonic simulation** | a 14 × 10 m indoor world with rooms, doorways, furniture and *low obstacles the lidar can't see* |
| 👀 **Sensors** | 360° lidar, RGB-D depth camera, IMU, wheel encoders |
| 🧭 **Localization** | EKF sensor fusion (wheel odometry + IMU), SLAM mapping, or AMCL on a saved map |
| 🗺️ **Navigation** | Nav2 with the Smac planner, MPPI controller, 3D voxel costmaps that use the depth camera, and a collision monitor |
| 🤖 **Autonomous exploration** | a frontier explorer that maps unknown space by itself, then drives back home |
| 🎮 **Manual and autonomous modes** | drive with the keyboard; one key switches between MANUAL and AUTO, and any drive key takes over |
| 🧪 **Learning material** | 14 guides, 8 hands-on labs, a runnable Nav2 Python example, unit tests and CI |

## Quick start (about 15 minutes)

On **Ubuntu 24.04** with **ROS 2 Jazzy** installed ([full install guide](docs/01_installation.md)):

```bash
sudo apt install ros-jazzy-ros-gz ros-jazzy-navigation2 ros-jazzy-slam-toolbox \
  ros-jazzy-robot-localization ros-jazzy-xacro ros-jazzy-joint-state-publisher-gui python3-scipy
git clone https://github.com/osama13robot/ros2-autonomous-rover.git ~/ros2-autonomous-rover
cd ~/ros2-autonomous-rover
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install
./scripts/start_sim.sh
```

Gazebo and RViz open, followed by a keyboard window. Click into the keyboard window, then:

* hold **`w a s d`** to drive
* press **`2`** to switch to **AUTO**: the robot starts exploring and mapping by itself
* press any drive key to take back control

Next: [Quick start guide](docs/02_quick_start.md) → [Hands-on labs](docs/10_hands_on_labs.md).

## What has been tested

Everything below was run in simulation on the reference machine (Ubuntu 24.04, ROS 2 Jazzy,
Gazebo Harmonic 8.7, CPU-only rendering):

* **Drive base:** 0.3 m/s for 4 s gave 1.20 m of odometry; a commanded 90° turn measured 90.0°.
* **Autonomous exploration:** 131 m² mapped with no human input, then the robot drove back to the
  start. The SLAM pose was within about 1 cm of Gazebo's ground truth.
* **Saved-map navigation (AMCL):** reached a goal in another room, 6 cm from ground truth.
* **Waypoint patrol example:** all 5 waypoints across 4 rooms reached, finishing back home.
* **Low-obstacle avoidance:** the robot went around a 10 cm brick that the lidar can't see, using
  only the depth camera, with 0.41 m of clearance.
* **Mode switching:** keyboard commands pass only in MANUAL; switching to MANUAL cancels Nav2 goals; a
  drive key in AUTO takes over.
* **Unit tests:** `colcon test` passes 4 tests covering frontier detection and the velocity logic.
* **Printable parts:** all 9 STL files are verified watertight by the generator.

The real-robot driver launch (`robot.launch.py`) is a **template that has not been tested on hardware**.
See [Building the real robot](docs/11_real_robot.md).
